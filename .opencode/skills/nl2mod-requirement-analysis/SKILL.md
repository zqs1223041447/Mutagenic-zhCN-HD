# 自然语言需求分析规则（skill 适配层）

> **执行适配层，不是政策制定者**（AGENTS.md L0 权威）。本 skill 只负责"何时按需加载 + 指向权威文档"。

## 何时使用

用户输入是**自然语言需求描述**（而非明确执行命令）时，按以下流程：

1. 按需加载完整规则：读取 `docs/ai/nl2mod-requirement-analysis.md`（L2 权威文档）。
2. 遵循其中的分析流程与输出格式，**未经用户确认不修改工作区**。

## 核心要点（速记，完整细节以文档为准）

- 默认只读分析：需求 → 理解 → 区分类型 → 查当前实现 → 可行性 → 方案 → **等确认** → 执行。
- 不把猜测当事实、不把问题当功能需求、不擅自填未知参数（X/某地图/若干）。
- 用户建议的实现方式只是候选方案，先对比再选。
- 汉化问题找根因（公共机制），不只修单条字符串。
- POEDB 仅作机制/数据参考，不复制 POE 代码结构。
- 特殊机制优先做成通用能力（Trigger/Condition/Effect），再让物品数据引用。
- 输出格式：需求理解 / 当前情况 / 可行性 / 推荐方案 / 未确定项 / 执行范围。
